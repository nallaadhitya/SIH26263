# Phase 5 local ML service

Phase 9 selects MySQL behind Express's storage interface. Python still receives only the same four de-identified numeric/null aggregates and never connects to MySQL. Database transactions are released before Python network calls; input freshness is checked again afterward. MySQL smoke verification uses separate test databases through `SMOKE_STORAGE_DRIVER=mysql`; missing test database setup fails explicitly. See [mysql.md](mysql.md).

The service identifies unusual **synthetic programme/year aggregate patterns** for human review. It does not identify fraudulent students, determine noncompliance, authenticate APAAR IDs, or query official services. Express remains the application backend and the only component accessing application JSON under `data/`.

## Architecture and files

`ml-service/ml_app/` contains strict schemas, synthetic generators, feature engineering, offline training, trusted artifact loading/inference and FastAPI routes. `backend/ml/` contains scoped aggregate extraction, a bounded HTTP adapter, orchestration and an Express router. Existing student CRUD/import, JSON storage and deterministic compliance modules remain intact. No ML result is written into `validation-issues` or another application collection.

Python never reads `data/`. Synthetic CSV datasets, model artifact, manifest and evaluation report are generated under ignored `ml-service/artifacts/`. Requests cannot supply file/model paths, training parameters, institution references, names or APAAR values. Training code is not imported by API code, and no training endpoint exists.

## Environment and setup

Tested on Windows with Python **3.10.7**, Node **22.20.0**, and the pinned Python packages in `ml-service/requirements-lock.txt`. Core dependency choices are listed in `requirements.txt`; the lock records the full resolved environment. This phase uses FastAPI 0.121.3, uvicorn 0.38.0, pandas 2.3.3, NumPy 2.2.6, scikit-learn 1.7.2 and SciPy 1.15.3, plus Pydantic, joblib and test dependencies. Do not assume identical floating-point outputs with different package versions.

From the project root in PowerShell:

```powershell
python -m venv ml-service/.venv
.\ml-service\.venv\Scripts\python.exe -m pip install --no-cache-dir -r ml-service/requirements-lock.txt
cd ml-service
.\.venv\Scripts\python.exe -m ml_app.train
.\.venv\Scripts\python.exe -m pytest -q
```

No virtual-environment activation or PowerShell execution-policy change is needed. The training command prints actual synthetic metrics and creates:

- `artifacts/model.joblib`: fitted preprocessing and Isolation Forest pipeline.
- `artifacts/manifest.json`: model version, feature orders, threshold, configuration, dependency version, training source/hash and artifact integrity hash.
- `artifacts/evaluation.json`: labelled synthetic evaluation results.
- `artifacts/synthetic-training.csv` and `synthetic-evaluation.csv`: separate generated datasets for inspection.

The default artifact directory is relative to the project root: `ml-service/artifacts`. An optional `ML_MODEL_DIR` must also be relative and remain inside `ml-service/`. No environment setting is required for the default path.

`joblib` is pickle-based: **load only artifacts generated by this trusted local trainer**. The SHA-256 manifest check detects corruption/mismatch, not a malicious OS user who replaces both files. There is no artifact upload endpoint. Stop Python before training/replacing artifacts, then restart it; there is no live model reload.

## Feature definitions

The unit of evaluation is one authenticated institution's existing programme/academic-year group. Institution/programme/year identifiers remain in Express. Python receives only ordered numeric rows; responses use positional indexes that Express maps back to its own group references.

| Input feature | Definition | Missing/domain handling |
| --- | --- | --- |
| active_record_count | Number of institution-owned stored rows in the programme/year whose status is `active` | Required integer 0–100000; engineered as `log1p(count)` in Python |
| intake_ratio | Phase 4's known policy-counted enrolment divided by approvedSeats | Null without one applicable counting policy, a complete resolved count, or positive capacity; otherwise 0–20 |
| year_over_year_change | `(current policy-counted enrolment - previous count) / previous count` for exact consecutive academic years | Null without known resolved counts, a positive prior count, and matching status/category counting bases; otherwise -1–20 |
| admission_year_concentration | Largest admission-year bucket divided by active rows in this programme/year | Null for no active rows or incomplete/malformed admission years; otherwise 0–1 |

Raw active-row count is not a verified count of distinct students; duplicate/invalid stored rows can influence it. Intake ratio and historical comparison deliberately reuse the deterministic engine's counting methodology, but **finding codes, severities, compliance decisions, labels, names and APAAR identifiers are not model inputs**. Ratio reflects the same capacity facts used by deterministic compliance; a high-ratio anomaly is not an independent discovery of a violation. Admission concentration is a record-distribution descriptor, not an admission-category quota check. No sensitive personal/demographic fields or official APAAR status are features.

Historical change is missing if no comparable policy-backed history exists; it is never fabricated as zero. Admission-year ranges may differ across years, but the included statuses/category treatment must match. A missing current intake policy produces null ratio/change and a `missingFeatures` list, not an inferred quota. Unknown programme/year rows are not sent; Express reports their institution-scoped `skippedRecords` count for deterministic/manual review. Counts outside the supported model domain return explicit errors rather than being clipped or silently marked normal.

The feature version is `aggregate-features-1.0.0`. No student write or import is changed by feature extraction. Input groups are sorted by programme and year; actual numeric feature ordering is fixed and recorded in model metadata.

## Pipeline and score interpretation

The offline trainer generates 800 synthetic normal rows using NumPy seed **42**. For each of the three nullable inputs, approximately 10% of the generated training values are missing. Python applies `log1p(active_record_count)`, then a fitted `SimpleImputer(strategy="median", add_indicator=True, keep_empty_features=True)`, fitted `StandardScaler`, and `IsolationForest` with:

```text
model_version: synthetic-isolation-forest-1.0.0
n_estimators: 200
max_samples: 256
random_state: 42
contamination: auto
n_jobs: 1
```

The four engineered base features are followed by three fitted missing-indicator features. Both orders and preprocessing configuration are recorded in the manifest. Preprocessing is fitted **only on training data**, never request or evaluation data. API inference calls `score_samples` only; it cannot retrain.

`anomaly_score = -pipeline.score_samples(features)`: higher means more unusual, not a probability. The review threshold is the **99th percentile of training-normal scores**, currently **0.6345783537256784**. `review_flag = anomaly_score >= threshold`. This explicit threshold is used instead of Isolation Forest's default `predict`/offset decision. See the [scikit-learn IsolationForest reference](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.IsolationForest.html) and its [preprocessing leakage guidance](https://scikit-learn.org/stable/common_pitfalls.html).

The imputer handles missing features using training medians and missingness indicators. Responses list missing inputs so a score based on partial evidence is visible. Scores do not explain causality or allocate responsibility to a student/institution. There is no feature-attribution or confidence/probability claim.

## Synthetic evaluation and actual results

The generator creates a separate held-out dataset with seed **2026**: 200 synthetic normal rows and 60 deliberately extreme rows (large counts/ratios/growth and lower concentration). Labels describe those generation rules, not real-world outcomes. Training and evaluation rows are disjoint; the training frame has no labels. Evaluation data/labels are never used for preprocessing fit, model fit or threshold selection.

Actual local evaluation with the pinned environment:

| Metric | Synthetic-demo result |
| --- | --- |
| Precision | 0.9230769231 |
| Recall | 1.0 |
| F1 | 0.96 |
| True normal, predicted normal | 195 |
| True normal, flagged for review | 5 |
| True unusual, predicted normal | 0 |
| True unusual, flagged for review | 60 |

Confusion matrix: `[[195, 5], [0, 60]]`, with rows true normal/unusual and columns predicted normal/review. The threshold was fixed from training data before computing these results. The report is regenerated by `python -m ml_app.train` and includes dataset fingerprints for traceability.

The synthetic columns are simple generated distributions, not a representative dataset of actual institutions. The unusual examples are deliberately easy extremes; metrics do not demonstrate subtle anomaly detection, demographic fairness, fraud detection, real-world precision or regulatory compliance. Valid small/new/empty programmes can look unusual relative to this training distribution. Additional independent, ethically sourced evidence and policy would be needed before any real use.

## Python API (internal only)

| Method/path | Access and behavior |
| --- | --- |
| GET `/health` | No key; returns status/model availability only. 503 if model or key configuration is unavailable |
| GET `/model/info` | Requires `X-ML-Service-Key`; returns metadata and limitations |
| POST `/predict` | Requires internal key; strict numeric feature batch; returns scores/review flags |

Python binds only to loopback in documented commands. No CORS access is enabled, browser `Origin` headers are rejected, and interactive docs are disabled. An Express session cookie is not an internal service credential. Requests are limited to **64 KiB**, including chunked bodies, and **1–100 rows**. Unknown fields, stringified numbers, booleans, invalid bounds, NaN/infinity, malformed JSON and empty batches fail safely without echoing values. Missing optional features may be omitted or null; active count is mandatory.

Internal request example, sent by Express (no identifiers):

```json
{
  "records": [{
    "active_record_count": 80,
    "intake_ratio": 0.72,
    "year_over_year_change": 0.03,
    "admission_year_concentration": 0.8
  }]
}
```

Response shape (the score below is illustrative):

```json
{
  "model_version": "synthetic-isolation-forest-1.0.0",
  "source": "ml_anomaly",
  "threshold": 0.6345783537256784,
  "results": [{ "index": 0, "anomaly_score": 0.4, "review_flag": false, "missing_features": [] }]
}
```

Errors return static JSON: 401 invalid internal key, 403 browser origin, 413 too large, 422 invalid feature request, 503 missing model/key, 500 inference failure. Validation errors do not return Pydantic's input echo. API handlers do not log feature payloads; startup uses `--no-access-log`.

## Express API and freshness

`POST /api/v1/ml/evaluate` uses the existing cookie session, CSRF header, central `ml:evaluate:own` permission, institution enforcement and a 10-request/IP/15-minute limit. Institution admins/operators are allowed; reviewers/verifiers are denied all ML results. Account status/role/institution are rechecked after inference before results are released.

Body is `{}` or optional exact `programmeId`, `academicYear`, and matching `institutionId`. No client features, model URL, training option or query parameter is accepted. A foreign programme filter produces `no_data` without revealing whether it exists elsewhere. Filters never choose another institution. A maximum of 100 groups can be scored at once; narrow filters if needed.

Response includes `source: "ml_anomaly"`, model/feature versions, threshold, observation time, `status` (`evaluated` or `no_data`), `skippedRecords`, `stale`, `freshness`, `authenticityVerified: false`, and scoped `results` with `institutionId`, `programmeId`, `academicYear`, `anomalyScore`, `reviewFlag`, and `missingFeatures`. There is no claim of overall compliance or per-student fraud. `no_data` means no assessment was performed, not normal behaviour or a healthy downstream service.

The adapter checks HTTP status/content type, response size, exact keys, known model version, row count/index order, finite score bounds, missing-feature order and review decision consistency. Redirects/remote URLs are refused. Python failure is never converted into normal scores. Missing/unavailable configuration/service returns 503, timeout 504, malformed or failed upstream responses 502, and invalid aggregate domain 422. Storage errors use the existing safe 500 handler. Responses use `Cache-Control: no-store`.

ML results are intentionally **not persisted** and do not overwrite deterministic findings. Scoped source-input fingerprints are compared before and after inference; changed inputs return `stale: true` and `freshness: "stale"`. Unchanged checked inputs return `matches_checked_inputs`. These reads are not a cross-file transaction or lock against future changes; reevaluate after edits. There is no cached/current ML finding collection or durable ML history in this phase.

## Tests and real HTTP smoke test

From the respective directories:

```powershell
# backend/
npm test
# ml-service/
.\.venv\Scripts\python.exe -m pytest -q
# backend/, after Python training:
npm run smoke:ml
```

Tests cover strict schema/missing values, deterministic scores, training/evaluation separation, feature ordering, metadata, deliberately unusual examples, size/batch limits, API privacy, trusted artifact loading, timeouts, malformed results, permissions, institution isolation, mid-request changes and separation from compliance snapshots. All original Phase 1–4 tests remain intact. Pytest temporary directories stay inside ignored `ml-service/tests/.tmp-*` paths. A Starlette/AnyIO dependency deprecation warning may appear; it does not affect passing tests.

`backend/jest.config.js` gives integration tests a bounded 30-second execution budget for real cost-12 bcrypt operations on slower machines; a measured six-operation run took 7.8 seconds outside Jest, exceeding its former five-second default. Assertions, hash costs and explicit ML timeout tests are unchanged. The random unknown-user dummy hash is generated once per module instead of per app instance. Jest also uses its [documented Math sandbox optimization](https://jestjs.io/docs/30.0/configuration#sandboxinjectedglobals-arraystring) to reduce VM global-lookup overhead.

The smoke script starts real Uvicorn and Express processes on temporary loopback ports, checks health/private API access, scores synthetic normal/unusual examples, then logs into Express and runs end-to-end institution-scoped inference. It uses generated ephemeral credentials and an isolated ignored test directory, stops both services and removes only its own fixture directory. It does not change runtime user/student data or require a committed secret.
